title: Make
description: L'app Branch Pilot pour Make — décider avec une décision de votre compte, ou en créer une depuis le module.
---

<Note>
L'app Branch Pilot est partagée par **lien d'invitation** jusqu'à sa publication dans le catalogue Make. Sans elle, le module HTTP en bas de page fait le travail.
</Note>

## Avec l'app Branch Pilot

<Steps>
  <Step title="Connectez">
    Ajoutez le module **Branch Pilot → Make a decision** et créez une connexion avec une clé API (Branch Pilot → Réglages → Clés API).
  </Step>
  <Step title="Choisissez ou créez la décision">
    Le champ **Decision** propose quatre sources :

    - **Use an existing decision** — une décision de votre compte. Les champs d'entrée sont générés depuis son contexte déclaré.
    - **Create from a template** — une décision prête à l'emploi du catalogue (routage de leads, tri de tickets, sentiment…), avec ses cas de test. Les champs d'entrée viennent du template.
    - **Create a new decision** — un nom, un type (route, score ou classify), les options / niveaux / étiquettes avec une phrase chacun, et la question posée sur l'entrée.
    - **Describe it in a sentence** — un nom et une description avec vos mots. Branch Pilot rédige les options et la question, dans la langue de la description.

    Une décision créée depuis le module apparaît dans votre compte **à la première exécution du scénario**, puis le scénario la réutilise : le nom l'identifie. Affinez les options, les exemples de référence et le seuil de confiance dans Branch Pilot, pas dans le module.
  </Step>
  <Step title="Routez sur la réponse">
    Ajoutez un **Router** après le module. Sur chaque route, filtrez sur `choice` : égal à `sales`, `support`, `spam`… et une route pour `__uncertain__`. Pour une décision score, filtrez sur `score` (0–100) ; pour une classification, sur `labels` contenant une étiquette. `decision_created` vaut vrai lors de l'exécution qui a créé la décision, avec `decision_url` qui pointe vers elle.
  </Step>
</Steps>

<Warning>
Sur le plan Free, trois décisions peuvent être en ligne à la fois. Une décision créée au-delà reste en **brouillon** et le module s'arrête avec une erreur explicite : passez au plan supérieur, puis publiez-la dans Branch Pilot.
</Warning>

<Tip>
Chaque source appelle les mêmes endpoints : `POST /decisions` (créer ou réutiliser) puis `POST /decide/{slug}`. N'importe quel client peut faire de même.
</Tip>

## Avec le module HTTP

<Steps>
  <Step title="Ajoutez un module HTTP → Make a request">
    - **URL** : `https://api.branchpilot.ai/v1/decide/lead-routing` (le slug de votre décision)
    - **Method** : POST
    - **Headers** : `Authorization: Bearer bp_live_…` et `Content-Type: application/json`
    - **Body type** : Raw, **Content type** : JSON
    - **Parse response** : oui
  </Step>
  <Step title="Mappez l'entrée">
    Dans le corps, mappez les champs du module précédent :

    ```json
    { "input": { "email": "{{1.email}}", "message": "{{1.message}}" } }
    ```
  </Step>
  <Step title="Routez sur la réponse">
    Ajoutez un **Router** après le module HTTP. Sur chaque route, filtrez sur `{{2.data.choice}}` : égal à `sales`, `support`, `spam`… et une route pour `__uncertain__`. Pour une décision score, filtrez sur `{{2.data.score}}` ; pour une classification, sur `{{2.data.labels}}` contenant une étiquette.
  </Step>
</Steps>

<Tip>
Stockez la clé API dans une **connexion** Make ou une variable de scénario plutôt que dans le corps du module, pour qu'elle n'apparaisse pas dans le blueprint du scénario.
</Tip>
